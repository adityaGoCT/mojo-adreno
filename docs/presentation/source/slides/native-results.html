Faster where barriers dominate: the native barrier orders shared memory only.

Mojo and MAX on Adreno · 17 · Mesa Turnip · ms, median of 20 runs · SGEMMs 1024³ · vector add varies run to run

Here is the scorecard: the same eight kernels, the same Turnip driver, the same runner, compiled once through the retargeter and once through the native target. Every kernel passes the full output check both ways. Speed is the same or better. Vector add, warp sum, naive SGEMM and register-tiled SGEMM are level; small kernels like vector add vary by a few tenths of a millisecond from run to run. The two kernels that lean on barriers are faster natively: block sum by more than two times and the fp16 tiles by 15 percent. That is not magic. The retargeter’s barrier also orders global memory, as CUDA’s __syncthreads does; the native barrier orders shared memory only, like GLSL’s barrier, because LLVM has no intrinsic for the in-between variant. For these kernels that is all they need, but it is a semantic difference worth knowing about.
