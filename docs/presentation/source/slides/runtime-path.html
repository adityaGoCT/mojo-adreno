Mojo and MAX on Adreno · 27 · driver interface: SDK/include/HAL in modular/modular · plugin: driver/ in mojo-adreno

So what does it take to really run MAX on the phone? Four pieces, and three are now done. First, a Vulkan driver plugin. MAX defines a C interface for new devices, about sixty functions covering devices, memory, queues, events and loading kernels. Ours now runs on the phone itself: it implements that interface on Vulkan, batches 64 launches into each submission, and a launch costs 6.5 microseconds; the remote device of the last slides shares its code. Second, the runtime libraries built for Android: the fork now has an Android build configuration, taken from another developer's Android OpenCL port, plus two fixes of ours, one for the newer NDK and one in Mojo's standard library, which called glibc-only functions on Android. Third, compiling on the Mac and running on the phone: Mojo programs are compiled on the Mac with their kernels inside as SPIR-V, so the phone never runs the compiler; for MAX graphs, the same idea means shipping a compiled .mef file, which is next. Fourth, every operation a model uses has to compile for this target, run correctly, and then be tuned. For our 25 test graphs, ResNet-18 included, compiling and running correctly are done; speed and tuning are open-ended, and that is where Modular’s own vendor-specific kernels will need Adreno-specific versions.
