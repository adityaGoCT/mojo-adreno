Mojo and MAX on Adreno · 19

Act five, and the question everyone asks next: if Mojo now compiles for the Adreno, does MAX run there? Not yet, and it helps to split MAX into layers. The compiler and the standard library: yes, that is the target we just built. MAX’s GPU programming layer, the thread indices, barriers and warp operations that kernels are written with: yes, through the plugins. The runtime, the part that finds a device, allocates its memory and launches kernels, is not ported: it has device backends for CUDA, HIP and Metal and a plugin interface, but nothing for Vulkan, and it is not built for Android at all. The Python API and the model pipelines would additionally need Python on the phone, or MAX’s C API. So today, on the phone, our own small C programs do what the MAX runtime would do. The two layers in the middle, the kernel library and the graph compiler, can be tested without a phone at all. The short answer: the graph compiler runs for a virtual Vulkan device, and all 25 of our test graphs, ResNet-18 included, now compile to valid SPIR-V. And the kernels of 13 of them already run on the phone and match NumPy. The next two slides have the details.
