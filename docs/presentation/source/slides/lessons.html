Mojo and MAX on Adreno · 28

Five things to take away. One: Mojo’s LLVM IR turned out to be a workable bridge. With a retargeter we got a real model running on a GPU Mojo never targeted, token for token identical to PyTorch. Two: when it was slow, the cause was almost never SPIR-V as such. It was one specific lowering, the warp sum, which cost a factor of 4.9 on Llama until we fixed it. Three: the drivers decide. Two Vulkan drivers on the same chip disagree about what is fast, and twice about what is correct, so every run checks every output. Four: the native compiler target did not make anything faster than the retargeter at its best, but it made the whole path robust and much simpler, and it lives where the information is. The limits of SPIR-V and the drivers remain. And five: Mojo’s plugin design is real. A new GPU target, with enough fixes to compile every one of our MAX test graphs, ResNet-18 included, was about twenty-six hundred lines of C++ and Mojo. And MAX’s device plugin interface is real too: about fifteen hundred lines more, plugin and phone executor, let MAX run ResNet-18 on the phone from the Mac. Running it on the phone alone needs the runtime built for Android, and that is the long pole now.
