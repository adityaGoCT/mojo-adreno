Mojo and MAX on Adreno · 22 · remote/ in mojo-adreno, about 1,500 lines · MAX built with --//:hal_device_context=true

A test script can run single kernels, but whole models need MAX’s own host code to pick kernels and fill in their arguments. So we made the phone a device of MAX on the Mac. MAX has a plugin interface for new devices, about sixty C functions for memory, copies, kernels and launches. Our plugin implements it and forwards each call over adb to a small Vulkan program on the phone. Allocations get device addresses on the Mac side, and at each launch the plugin reads the kernel’s launch description to turn MAX’s arguments into Vulkan buffers and parameters. On MAX’s side it took about sixty lines: Vulkan as a known vendor, a hook for plain grid and block launches, and building MAX’s Mojo package for its plugin-based device layer. The result: all 25 graphs run on the phone through MAX’s own runtime, from additions and gathers to convolutions and the full ResNet-18, which matches MAX on the Mac’s CPU to six decimal places. At first it took 14 seconds per image, one network round trip per operation. Now the plugin streams its requests without waiting and the phone submits each kernel at once, so ResNet-18 takes 8.3 seconds, and all of that is GPU time, most of it in MAX’s naive convolution, which gives each thread one output pixel across all channels. That kernel is the next thing to fix. Running MAX on the phone itself would need an Android build of its runtime.
