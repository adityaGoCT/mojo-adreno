Mojo and MAX on Adreno · 20 · MAX 26.8 dev from source, virtual-device mode · compile only: nothing has run yet

Here is the compile test. MAX has a virtual-device mode for building models on machines without the GPU, so we added a Vulkan entry to it, pointed it at adreno710, and compiled 24 one-operation graphs plus a full ResNet-18, keeping every SPIR-V module and checking each with spirv-val. At first only two graphs compiled. Six fixes moved that. MAX kernels declare their block size through a metadata tag that had no value for our target. Reductions needed a warp-synchronize hook. Matrix multiply picked tensor-core paths this GPU does not have, so the Adreno target got its own branch to MAX’s plain SIMT kernel; on Adreno 8xx, with cooperative matrices, that branch is where a matrix-unit path would go. The big one: MAX passes tensors to kernels as structs holding device pointers, in memory, and Vulkan cannot load a pointer from memory. Passing them by value instead lets our backend give each tensor’s pointer its own buffer and its shape a slot in the params buffer. Then vector loads had to be split into per-element accesses, and atomics narrowed to the scopes and orderings Vulkan allows. Now 16 of 25 graphs give valid SPIR-V for every kernel, including all three matrix multiplies and the reductions. Three more compile but trip LLVM 24’s structured-control-flow bug, and six still fail, ResNet-18 among them. One caution: this is compile only. Nothing has run, so correctness is untested until there is a runtime on the phone.
