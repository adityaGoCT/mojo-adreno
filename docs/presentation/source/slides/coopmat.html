Mojo and MAX on Adreno · 23 · max.gpu.compute.arch.mma_spirv · matmul/gpu/adreno in MAX’s kernels · Samsung Remote Test Lab

The Adreno 710 has no matrix units, but newer Adrenos do, and Vulkan reaches them through one extension: cooperative matrices. A cooperative matrix is a tile that a whole subgroup loads, multiplies and stores together, while the driver decides which thread holds which element. We added a second target, adreno840, whose kernels can use them. In Mojo it is a small type, CoopMatrix: zero, load, multiply-add, cast and store, and the loop on the slide is a complete matrix multiply. Each operation is a call to a marker function that passes the matrix as an opaque handle. Our kernel pass already knew which buffer and element every pointer reaches, so it also rewrites the markers into the SPIR-V instructions, giving each handle its matrix type, including the accumulator that the K loop carries. LLVM’s SPIR-V backend knew these instructions, but only for OpenCL, so a 14-line patch lets Vulkan shaders use them. Then we ran it. Samsung’s Remote Test Lab rents out a Galaxy S26 Ultra, a Snapdragon 8 Elite Gen 5 with an Adreno 840, and bridges it to the Mac’s adb. Its driver offers tiles 64 rows tall, 16 to 64 wide, fp16 or fp32, but no fp16 into fp32, so half-precision products accumulate in half precision, and the results match, bit for bit, a model that rounds every step to fp16. With 64 by 64 tiles, a 2048 matrix multiply runs at 2.1 teraflops in fp16 and 1.3 in fp32, more than three times the narrow tiles. MAX’s matmul now takes this kernel on that target for all-fp16 and all-fp32 shapes in multiples of 64; its three test matmuls pass on the phone, the fp16 one eight times faster than MAX’s naive kernel on the same phone, and all 26 graphs still compile. What is left is tuning: shared-memory staging, fused epilogues, and integer products.
