Mojo and MAX on Adreno · 23 · max.gpu.compute.arch.mma_spirv · matmul/gpu/adreno in MAX’s kernels · compile-only

The Adreno 710 has no matrix units, but newer Adrenos do, and Vulkan reaches them through one extension: cooperative matrices. A cooperative matrix is a tile, here 16 by 16, that a whole subgroup loads, multiplies and stores together, while the driver decides which thread holds which element. We added a second target, adreno840, whose kernels can use them. In Mojo it is a small type, CoopMatrix: zero, load, multiply-add, cast and store, and the loop on the slide is a complete matrix multiply. Each operation is a call to a marker function that passes the matrix as an opaque handle. Our kernel pass already knew which buffer and element every pointer reaches, so it also rewrites the markers into the SPIR-V instructions, giving each handle its matrix type, including the accumulator that the K loop carries. LLVM’s SPIR-V backend knew these instructions, but only for OpenCL, so a 14-line patch lets Vulkan shaders use them. MAX’s matmul now takes a matrix kernel for fp16 shapes in multiples of 16 on that target, one subgroup per tile, accumulating in fp32. Compiled for that target, all 26 of our MAX test graphs build, one of them a new transposed half-precision matmul, every one of their 213 kernels passes the SPIR-V validator, and both half-precision matmuls take the matrix kernel. Nothing of it has run yet: neither driver on our Adreno 710 offers the extension, so the next step is a phone with an Adreno 8xx.
