Mojo and MAX on Adreno · 28 · android/ and driver/ in mojo-adreno · Galaxy S26 Ultra, Adreno 840, stock driver

And here is that path working. Every model's forward pass now also exists as Mojo host code: a loop of DeviceContext launches of the same kernels, compiled for Android with the kernels inside as SPIR-V. It runs through MAX's own DeviceContext, the HAL one, on MAX's runtime cross-built for Android, and on our Vulkan driver plugin, which implements MAX's driver interface on the phone. The table compares it with the hand-written C runners. Llama 3.2 1B decodes at 24.7 tokens a second with fp16 weights and 78.1 with 4-bit weights, against 23 and 75 for its C runner. Bonsai 2 2B runs the Android port's own model.mojo, unchanged apart from asking for Vulkan instead of OpenCL, at 74 to 76 tokens a second against 80. The ternary Qwen3-8B decodes at 25.1 against 25. Every row matches its reference token for token. Two details make it practical. A launch through DeviceContext costs 6.5 microseconds, because the plugin batches 64 launches into each Vulkan submission; one submission per launch cost 105. And the weights never cross the slow adb bridge of a remote phone lab: the phone downloads each public checkpoint from Hugging Face and converts it itself, into exactly the bytes the Mac's exporter writes.
