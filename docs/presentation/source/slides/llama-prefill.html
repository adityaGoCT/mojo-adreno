This is what the matrix units are for. Generating text is one token at a time: every token reads all 2.5 gigabytes of weights once, so decode is limited by memory bandwidth. On the S26 Ultra it runs at 43 milliseconds a token, against 285 on the Adreno 710, with the same Mojo kernels. Reading the prompt is different. Our runtime used to push it through the decode path one token at a time, so a 431-token prompt took 17.7 seconds. Processed together, every projection becomes one matrix multiply over all the prompt tokens, and each weight is reused 431 times. We wrote batched versions of the kernels, compiled with the adreno840 target, and the matrix multiply runs on cooperative matrices in fp32: the fp16 weights are converted while they are staged in shared memory, so the arithmetic stays as accurate as before. The prompt now takes 0.63 seconds, 28 times faster, and all 48 generated tokens are identical to PyTorch. Most of that time, 556 milliseconds, is the matrix products at about 1.8 teraflops; getting there took coalescing the weight copy, which doubled its speed. Attention is fused too: one subgroup handles 64 prompt tokens of a head, with both of its matrix products on the matrix units, in 46 milliseconds for all 16 layers. Along the way the phone came back from the lab on Android 17 with a driver that reports the same version number but rejected our matrix code until the compiler wrote its zero matrix as a constant.
