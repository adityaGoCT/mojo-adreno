Mojo on the Adreno 840 · 11 · android/ and driver/ in mojo-adreno · Galaxy S26 Ultra and Z Fold, stock driver

Until now, each model ran from a hand-written C runner. Every model's forward pass now also exists as Mojo host code: a loop of DeviceContext launches of the same kernels, compiled for Android with the kernels inside as SPIR-V. It runs on MAX's own DeviceContext, on MAX's runtime cross-built for Android, and on our Vulkan driver plugin, which implements MAX's device interface on the phone. The times match the runners. Llama 3.2 1B takes 40.6 milliseconds a token with fp16 weights and 12.8 with 4-bit weights, against 43 and 13. Bonsai 2 2B runs the Android port's own model.mojo, unchanged apart from asking for Vulkan, at 13.2 to 13.5 milliseconds, against 12.4 for a runner that records all 721 launches of a token once. The ternary Qwen3-8B takes 39.8 milliseconds against 40. Llama's batched prefill runs from Mojo too, its matrix kernels launched per layer: on a Galaxy Z Fold the 431-token prompt takes 0.65 seconds with fp16 weights and 0.59 with 4-bit weights, against 0.62 for the C runner. A first run on a phone also compiles the pipelines, 39 seconds for the fused attention on this driver build, for the C runner too; the plugin keeps a pipeline cache, so later runs skip it. Every row matches its reference token for token. A launch costs 6.5 microseconds because the plugin batches 64 launches into each Vulkan submission. And the phone now downloads each public checkpoint from Hugging Face and converts it itself, into exactly the bytes the Mac's exporter writes, so nothing large crosses adb.
