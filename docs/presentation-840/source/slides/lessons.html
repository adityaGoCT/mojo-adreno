Mojo on the Adreno 840 · 12

Five things to take away. First, on a phone the driver is the platform. The same chip with a driver reporting the same version number rejected our matrix code on Android 17 and failed to link our attention kernel on Android 16, and some quirks gave wrong numbers silently; every run checks every output. Second, the matrix units are for prompts. Generating one token is matrix-vector work, set by how many bytes the weights take, while a batched prompt is matrix work and runs six to 28 times faster. Third, the driver’s fp16-only sums set the ceiling: for accurate prompts we use fp32 tiles at two thirds of the fp16 speed, which is exactly what Qualcomm’s conversion extension would lift. Fourth, Mojo kernels carry over: a kernel file written for another developer’s OpenCL target ran unchanged through our Vulkan target, and its ternary projections then served a second model, Qwen3-8B. Fifth, the remaining gap is the runtime: each model still has a hand-written C runner around its kernels, where MAX would normally take over.
