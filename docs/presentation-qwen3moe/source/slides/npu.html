Then the NPU. The laptop’s Hexagon NPU is the same V81 HTP as the phones’, and we ran one real layer of this model on it in fp16, through ONNX Runtime’s QNN execution provider built for Windows on Arm: attention, the router, and the experts. The catch is that an HTP graph is static. It cannot gather the 8 experts a token chose, so the graph computes all 128 experts for every token and weights them with the router’s top 8, sixteen times the useful work. A token through one layer takes 10.7 to 14 milliseconds, which would be half a second or more a token for 48 layers, against 27 to 32 milliseconds for the whole token on the GPU. A 256-token prefill takes 95 milliseconds a layer, 4.6 seconds for the model, against about 2.8 on the GPU; at 128 tokens QNN compiles a worse plan, 10 seconds. The hardware itself is fast: it reads fp16 weights at about 100 gigabytes a second, faster than our GPU kernels, and runs 3.4 teraflops of fp16 matrix work. If it could read only the 8 chosen experts, a layer would take under a millisecond. It is accurate too, once the QK norms are written as L2 normalizations, because QNN refuses its RmsNorm on heads of 128. But the whole model in fp16 is 61 gigabytes, far more than the laptop has, so on the NPU it would need the quantized w4a16 path.
