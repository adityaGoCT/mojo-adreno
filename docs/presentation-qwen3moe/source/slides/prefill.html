Prefill is where a mixture of experts is unusual: the weights a token uses depend on the token, so there is no one weight matrix for the whole prompt. A layer splits in two. Attention has the same weights for every token, so all of the prompt’s tokens go through q, k, v and o at once, as in any batched prefill. Then the router picks each token’s top 8 experts. Before the experts run, the tokens are grouped by expert: each of the 128 experts gets the list of prompt tokens that chose it, about 25 each for a 404-token prompt. Each expert then runs once over its own tokens, a small matrix product with fixed weights, a grouped GEMM. Its weights are read once per layer instead of once per token, and an expert no token chose costs nothing. Finally each token’s eight outputs are added up with its router weights. The kernels give each lane a whole matrix row against 8 tokens, so each int4 word is decoded once for eight tokens; two layouts I tried first were no faster or ten times slower. The result: a 404-token prompt in 4.31 seconds instead of 12.0, and 2.6 to 2.8 times faster from about 96 tokens on. Below about 32 tokens most of the GPU sits idle, so short prompts still run a token at a time. The batched logits are within 1.5e-5 of the token-at-a-time path, with the same tokens.
