Decode: memory bandwidth

A token’s time is the bytes of weights read: 4-bit took Llama from 43 to 13 ms; Mojo launches cost nothing measurable. After 1000 prompt tokens, Qwen3’s KV cache slows it to 17.0 tok/s.

Prefill: the matrix units

All prompt tokens at once reuse every weight: fp32 cooperative-matrix products at about 1.8 TFLOP/s, 4 to 28 times faster, from Mojo as from C.

Prompts: Llama 431 tokens (prefill) and 46 (decode), Bonsai 412 and 19, Qwen3 408 (Llama’s passage) and 19 · Galaxy S26 Ultra, Z Fold (Mojo prefill) and SM8850 reference phone

Here are the results for every model, all on an Adreno 840 with Qualcomm’s stock driver, and all checked against a reference. Decode now has two columns: the Mojo host code, where the forward pass is Mojo DeviceContext code running on the phone, and the C runners it replaces. Llama 3.2 1B generates 24.7 tokens a second with fp16 weights through Mojo, against 23 for its C runner, and 78.1 with 4-bit weights against 75. Bonsai 2 2B runs the Android port's own model.mojo at 74 to 76 tokens a second; its C runner, which records a token's 721 dispatches once, reaches 80. The ternary Qwen3-8B, the largest model, generates 25.1 tokens a second through Mojo and 25 through C. So launching each kernel from Mojo costs nothing measurable: decode is bound by memory bandwidth, one token is a matrix-vector product, and its time is the bytes the weights take. Fewer bits per weight is what took Llama from 43 to 13 milliseconds. Prefill, reading the prompt, runs batched on the matrix units: Llama reads 684 tokens a second, 0.63 seconds for 431 tokens, 28 times faster than one token at a time; Bonsai goes from 80 to 474 tokens a second. Llama's batched prefill now runs from Mojo too, as fast as its C runner: the same 431-token prompt in 0.65 seconds with fp16 weights and 0.59 with 4-bit weights, every generated token still matching PyTorch. Qwen3-8B now reads its prompt batched too, attention included on the matrix units: Llama’s passage, 408 tokens with its tokenizer, in 3.95 seconds, 103 tokens a second and 4.4 times faster than one token at a time; a 1000-token prompt in 9.4 seconds, 106 tokens a second, after which decode slows to 17.0 tokens a second, because every layer then reads 8 megabytes of KV cache. Every row matches its reference token for token, through Mojo and through C alike: PyTorch for Llama, MLX in FP32 for the ternary models.
