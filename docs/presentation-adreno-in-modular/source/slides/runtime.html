MAX’s runtime cross-built for Android · libM_driver_vulkan.so: MAX’s driver C API on Vulkan · Galaxy S26 Ultra, stock driver

This is how a model runs now, entirely in Mojo. The kernels are plain Mojo GPU functions, as before, and the forward pass is Mojo too: a loop of DeviceContext launches, the same code you would write for an NVIDIA or AMD GPU. The compiler builds it for Android: arm64 host code with every kernel inside as adreno840 SPIR-V. The weights never cross adb: the phone downloads each public checkpoint from Hugging Face and converts it itself, byte for byte what the Mac's exporter writes. At run time the program uses MAX's own DeviceContext, the HAL one, which is plain Mojo and loads a driver plugin. That plugin is ours: it implements MAX's driver C interface, about 60 functions, on Vulkan, and turns each launch's arguments into buffer bindings and params as the launch descriptions in the SPIR-V say. MAX's runtime itself is cross-built for Android with the configuration of the Android OpenCL port. The table compares the C runners this replaces. Llama's forward pass is 150 lines of Mojo instead of a 563-line C runner, Qwen3's 165 instead of 414, and Bonsai runs the port's own model.mojo, unchanged apart from asking for Vulkan instead of OpenCL. Speed is the same: a launch costs 6.5 microseconds because the plugin batches 64 launches into each Vulkan submission, so Llama decodes at 24.7 tokens a second against 23 for its C runner, Qwen3-8B at 25.1 against 25. Only Bonsai, with 721 small launches a token, gives up a few percent: 74 to 76 against 80.
