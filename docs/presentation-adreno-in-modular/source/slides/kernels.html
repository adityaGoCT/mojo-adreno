A Mojo kernel, and the SPIR-V it becomes

Subgroup: a lane shuffle and a warp reduction (64 lanes)

ss += shuffle_xor(ss, UInt32(8))
var s = warp_sum(x)

%lane = OpLoad %u32 %SubgroupLocalInvocationId
%src = OpBitwiseXor %u32 %lane %8
%t = OpGroupNonUniformShuffle %f32 %sg %ss %src
%s = OpGroupNonUniformFAdd %f32 %sg Reduce %x

Cooperative matrix: one 64 × 64 fp32 tile, from A (64 × 8) and B (8 × 64) in shared memory

var acc = Acc.zero()
var a = A.load(sa, 16)
var b = B.load[row_major=False](sb, 16)
acc = a.multiply_add(b, acc)
acc.store(out, ldy)

%C = OpTypeCooperativeMatrixKHR %f32 %sg 64 64 %Acc
%z = OpConstantComposite %C %f32_0
%a = OpCooperativeMatrixLoadKHR %A %sa %RowMajor %16
%b = OpCooperativeMatrixLoadKHR %B %sb %ColMajor %16
%c = OpCooperativeMatrixMulAddKHR %C %a %b %z
OpCooperativeMatrixStoreKHR %out %c %RowMajor %ldy

A, B and Acc are CoopMatrix[DType.float32, …] with MATRIX_A, MATRIX_B and ACCUMULATOR. Every pointer argument becomes storage buffer 0, 1, 2…; every number a slot of %params.

spirv-dis of normalize_qk, gemv and p_gemm_t2 from mojo-adreno’s builds · ids renamed for reading · %sg = subgroup scope

Here is what the backend produces, from real kernels. The first row is subgroup code. In Mojo you write shuffle_xor to exchange a value with the lane whose index differs in one bit, and warp_sum to add a value across the whole subgroup, 64 lanes on the Adreno. In the SPIR-V, the shuffle becomes the lane id read from the SubgroupLocalInvocationId builtin, an exclusive-or with the mask, and a GroupNonUniformShuffle at subgroup scope; the warp sum becomes a single GroupNonUniformFAdd reduction. The second row is a cooperative matrix, the matrix units. A, B and Acc are CoopMatrix types: a 64 by 8 tile of A, an 8 by 64 tile of B, a 64 by 64 accumulator, all fp32. In the SPIR-V each becomes an OpTypeCooperativeMatrixKHR, the zero accumulator a constant, the loads from shared memory carry their layout, row-major for A and column-major for B, and their stride, the multiply-add is one instruction, and the store writes the tile to the output buffer. The listings are spirv-dis output of our compiled kernels with the ids renamed so they can be read; around them, every pointer argument of the kernel is a storage buffer at the next binding, and every scalar argument a slot of one params buffer.
