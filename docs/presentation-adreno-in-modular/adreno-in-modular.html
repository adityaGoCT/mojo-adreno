A Mojo kernel, and the SPIR-V it becomes

Subgroup: a lane shuffle and a warp reduction (64 lanes)

ss += shuffle_xor(ss, UInt32(8))
var s = warp_sum(x)

%lane = OpLoad %u32 %SubgroupLocalInvocationId
%src = OpBitwiseXor %u32 %lane %8
%t = OpGroupNonUniformShuffle %f32 %sg %ss %src
%s = OpGroupNonUniformFAdd %f32 %sg Reduce %x

Cooperative matrix: one 64 × 64 fp32 tile, from A (64 × 8) and B (8 × 64) in shared memory

var acc = Acc.zero()
var a = A.load(sa, 16)
var b = B.load[row_major=False](sb, 16)
acc = a.multiply_add(b, acc)
acc.store(out, ldy)

%C = OpTypeCooperativeMatrixKHR %f32 %sg 64 64 %Acc
%z = OpConstantComposite %C %f32_0
%a = OpCooperativeMatrixLoadKHR %A %sa %RowMajor %16
%b = OpCooperativeMatrixLoadKHR %B %sb %ColMajor %16
%c = OpCooperativeMatrixMulAddKHR %C %a %b %z
OpCooperativeMatrixStoreKHR %out %c %RowMajor %ldy

A, B and Acc are CoopMatrix[DType.float32, …] with MATRIX_A, MATRIX_B and ACCUMULATOR. Every pointer argument becomes storage buffer 0, 1, 2…; every number a slot of %params.

Decode: memory bandwidth

A token’s time is the bytes of weights read: 4-bit took Llama from 43 to 13 ms; Mojo launches cost nothing measurable. After 1000 prompt tokens, Qwen3’s KV cache slows it to 17.0 tok/s.

Prefill: the matrix units

All prompt tokens at once reuse every weight: fp32 cooperative-matrix products at about 1.8 TFLOP/s, 4 to 28 times faster, from Mojo as from C.

MAX’s DeviceContext runs on the phone: its runtime on Android, our Vulkan plugin

Advantages

  • One model definition: the same MAX graph as on NVIDIA and AMD, no forward pass per model
  • The graph compiler fuses and plans memory: far fewer than today’s 615 to 721 launches a token
  • Pipelines bring the tokenizer, sampling, KV cache and serving
  • Compile on the Mac, ship a compiled model to the phone

Challenges

  • MAX’s graph executor still needs its Android build; the Mojo runtime and device plugin have theirs
  • Kernels must fit Adreno: 64-row tiles, fp16-only sums, 32 KB shared memory
  • Ternary and 4-bit formats are custom kernels today
  • Driver builds differ: every compiled graph needs checking on the device
  • Phone memory is shared and small: weights mapped once, compiling off the device

MAX’s device plugin interface: about 60 C functions, now on Vulkan (mojo-adreno driver/) · runtime: --config=android-arm64
